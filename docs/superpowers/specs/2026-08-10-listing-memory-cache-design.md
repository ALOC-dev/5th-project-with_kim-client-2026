# 매물 프론트 메모리 캐시 설계

## 목표

사용자가 홈 지도에서 다른 사이드바 화면으로 이동했다가 돌아오거나 매물 상세를 다시 열 때, 이미 조회한 매물 정보를 다시 요청하지 않고 즉시 복원한다. 캐시는 현재 브라우저 탭의 애플리케이션 실행 시간 동안만 유지하며 새로고침하면 비운다.

## 캐시 범위

### 지도 검색 결과

- 필터와 검색 중심 좌표를 조합한 안정적인 키로 검색 결과를 저장한다.
- 같은 키를 다시 요청하면 저장된 배열을 즉시 반환하고 API를 호출하지 않는다.
- 새로운 지도 위치 또는 필터 조합은 새로운 API 요청을 수행한다.
- 지도 이동으로 얻은 여러 검색 결과를 합쳐 보여주는 기존 동작은 유지한다.

### 매물 상세 정보

- `listingId`를 키로 상세 응답을 저장한다.
- 같은 매물을 다시 열면 캐시된 상세 정보를 즉시 사용한다.
- 목록에 있던 요약 정보보다 상세 응답을 우선한다.

## 중복 요청 처리

- 같은 검색 키 또는 같은 `listingId`에 대한 요청이 이미 진행 중이면 기존 Promise를 공유한다.
- 성공한 응답만 결과 캐시에 저장한다.
- 실패한 요청은 진행 중 캐시에서 제거하여 다음 시도에서 다시 호출할 수 있게 한다.

## 수명과 무효화

- 캐시는 모듈 메모리에 저장하며 탭 새로고침 또는 애플리케이션 재시작 시 초기화한다.
- 매물 수정처럼 서버 데이터가 바뀌는 동작은 현재 화면 상태를 우선 갱신한다. 이번 범위에서는 별도의 영구 저장이나 시간 기반 만료를 추가하지 않는다.
- 공개 매물 데이터이므로 사용자 로그아웃만으로 검색 캐시를 비우지 않는다.

## 사용자 경험

- 캐시 적중 시 중앙의 `매물 불러오는 중` 상태를 표시하지 않는다.
- 캐시가 없는 검색이나 상세 조회에만 기존 로딩 상태를 표시한다.
- 캐시된 지도 결과를 복원한 뒤 기존 군집화와 출입구 거리 계산을 그대로 수행한다.

## 테스트

- 같은 지도 검색 조건을 두 번 사용해도 API가 한 번만 호출되는지 검증한다.
- 다른 검색 조건은 각각 호출되는지 검증한다.
- 같은 매물 상세를 두 번 열어도 상세 API가 한 번만 호출되는지 검증한다.
- 실패한 요청은 다음 호출에서 재시도되는지 검증한다.
- 기존 지도 검색 결과 병합 테스트와 전체 테스트를 함께 실행한다.
